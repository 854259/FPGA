RTL 修复规则（仅在验证失败后加载）：

1. 先定位最早的根本错误，再处理连带错误。声明冲突、非变量过程赋值、过程块内 wire 属于编译问题，先修声明与作用域，不随意改功能或接口。
2. 若缺少 endmodule 或输出截断，用向量表达式、固定边界循环重写成精简完整实现；不续写半截代码，不保留长篇推导。
3. 若已进入仿真且 Mismatches 非零，先检查反馈中的候选位宽/截断警告，再核对复位、使能与加载优先级、非阻塞赋值旧值、输出延迟、计数首末拍及状态表。修正位宽不应无依据改变输出时序。
4. 错误输出名和首次出错时间只用来定位；仿真时间不等于周期编号。只有总错误数时，不推断未知的输入波形、预期输出或端口定义；保持题目给定语义。
5. 修复应针对反馈形成实质代码修改，不只改注释或原样返回。综合失败时保留已通过的功能行为，检查多驱动、时钟事件、锁存与不可综合语法。
6. 只返回一个完整 TopModule；不输出测试台、不请求或推测参考实现。
