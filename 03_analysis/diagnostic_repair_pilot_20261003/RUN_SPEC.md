# R1：固定候选的展开诊断修复小实验

收尾补记：本规格已执行，完整六调用两臂各三次均L0，展开均失败，按原门槛不晋级。结果与单列的中断轮见 `../codex_takeover_20261003/R1_RESULT.md`。下方保留事前设计，不因结果改门槛。

## 要回答的问题

在同一份稳定版失败候选、相同题面、相同技能和修复调用预算下，提供候选自身的真实 xelab 错误信息，是否比不提供诊断的重新检查更能恢复可展开性及官方等级？

本轮只回答一个已经触发的候选的条件修复效果，不是全题集、正常题回归、正式裸 baseline 增益或运行时成本验收。它也不直接验证声明自动补丁；那是另一机制。

## 两臂与预算

两臂均使用相同 system（稳定 7 规则＋同一反馈技能）、题面、完整初始候选及相同审查指令。唯一改变为 `Candidate diagnostics` 段落：

- D：5 条真实候选独立 xelab 错误；
- C：`No diagnostic text is provided.`，不暗示候选通过。

固定顺序为 **D0、C0、C1、D1、D2、C2**。每次都从冻结原候选开始，绝不串联修复。

每臂每次仅一次请求，最大输出 8192 tokens，temperature=0、top_p=1，单次客户端完整进程墙钟上限 300 秒，无重试、无后验挑选。3 对共 6 次，最大输出预算 49152 tokens，请求墙钟预算最多约 1800 秒加本地 I/O 与预检。原始候选的生成开销已经发生，两臂均不计作本轮推理。

不增加 seed 字段，与现有 runtime 一致。温度 0 的重复不保证确定性，这 3 次是同题重复，不是 3 个独立任务。这里的等预算指相同调用数、输出 token 和墙钟上限；真实输入/输出 token 与耗时另行报告，诊断臂输入更长。

模型固定为现有 `Qwen3.6-27B-Q4_K_M`，服务后端及 reasoning 配置不改。复用原样 `baseline.py` 的 `post_json()` 和 `extract()`，不调用旧开发 agent 的多套默认参数，不修改 baseline 或 runtime。请求、响应和候选均保存，不执行响应代码。

## 执行前置

1. 根执行者先验证修好的判定证据封装至少一题真实成功，确认日志实际落盘。若该链有问题，可以先保留本规格，不能用不可信判定宣布收益。
2. 核对没有在跑的质量评测，按既有 `/workspace/team/slot.sh` 协议取得唯一模型槽并记录本次 owner；该协议不是原子锁，不假定单凭 lock 文件就能消除竞争，仍核对现场进程。所有模型调用串行。
3. 检查工作盘空间。脚本自身输出很小，但判定工作目录占用需由执行者监控。
4. 使用隔离输出目录，不改提交包、共享技能或启动服务。冻结与运行之间不修改包中固定 baseline/技能。

本地 `dry_run/` 只演示 freeze 成功，包含本地包路径，**不能直接拿到云端 run**。云端按以下方式重新冻结为独立目录；命令中的路径是现有布局，owner 和输出目录需本轮唯一命名：

## 失败处理与固定判据

- 模型身份不符、槽归属或输入/技能变化、网络/协议/客户端超时：停整轮，保留部分产物和失败，返回非零；不重试补齐，不宣布有效配对。
- 非空正常协议返回但代码错误、截断或空答案：是候选结果，保留并送判，不能从分母移除。
- 超时后服务端可能还在计算：根执行者确认其结束后才能释放槽，不能因为客户端退出就宣称模型空闲，更不能杀共享模型。
- 六份完整生成产物均完成官方判定才分析，不看到第一份好答案就提前停止。
- 任一基础设施异常或判定证据缺失，则该轮“暂不可判定”；保留原记录，额外复判另存目录并说明原因，禁止覆盖原始 verdict。

固定报告为：两臂各 3 个等级、L0/L1/L2/L3 计数、系数均值及 3 个逐对差分；候选独立展开通过数；空答/截断；每次耗时、均值、最小/最大值及 tokens（不从 3 次样本估算 p95）。不报 pass@5 或“最高分答案”，不使用 156 的分母稀释本轮结果。

六次官方 verdict 直接交官方 `score.summarize()`，形式为每臂 `{task_id: [v0, v1, v2]}`，沿用官方系数和工具失败处理，并同时报有效数/计划数。三样本不能标“五样本验证”；本轮 C 臂也不是正式裸模型 baseline。

晋级规则：有效 3 对中 D 平均等级系数大于 C，且 D 的候选独立展开通过数不低于 C，才记为“单候选正面信号”，进入新题及正常守卫的下一轮；不直接上线。若均值相同但 D 展开更好，只能说改善了结构错误，未证明质量分优势；若结果相同或更差，归档本实现，只有新机制/证据才重开。3 对没有统计显著性承诺。

## 判定接线与下一步

本脚本不导入 `official_eval` 或官方测试台。根执行者在所有六份候选完成后，把每份 `solution.v` 与固定原任务交给已验证的 `official_eval.judge_sample()`（或其当前真实等价入口），每个样本独立判定目录，保存工具返回码、日志、判定器与输入哈希。外部判定的固定任务目录可包含官方测试台；它不得被重新注入任何模型请求。

候选单独 xelab 的通过数可由同一无测试台命令批量检查六份生成候选，保留完整 stdout/returncode；这是事后诊断，不用它从六份中挑最终答案。如果只完成官方判定而未做独立展开，报告该项未测，不把官方 L0 的所有失败原因都写成多驱动。

若进入扩大验证，才添加预先选定的正常守卫与其他触发样例；H3 的四道失败可作故障回归，但不能计入当前稳定版收益。本轮没有正常题调用，因此绝不声称零回归或全量经济性改善。
