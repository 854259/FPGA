## 3. 调用预算、超时与原候选保留

### 调用预算建议

首版采用**共享剩余调用预算**：已执行生成轮次为 `attempt`（从0开始），剩余调用数为 `repairs - attempt`。仅当大于0、选择器为review、剩余墙钟足够时复查；语义复查每请求至多一次，失败不再修复、重试或续接。

- 默认 `RTL_REPAIRS=1`：第一次生成直接编译成功，可增加一次语义复查；若先用一次模型调用修编译，则不再语义复查。
- 第一轮通过零模型调用的声明补丁修好：仍可以使用剩余一次复查，但选择器只看补丁后的候选。
- `RTL_REPAIRS=0`、skip、abstain、选择器异常、预算不足：返回当前候选，不追加调用；分别记录原因。
- 普通复查C与清单复查D使用完全相同的触发器、调用上限、输出token上限和检查规则，仅复查文本不同。此C不是官方裸模型baseline。

这保持请求总调用上限，却仍会增加许多原本只调用一次的请求的实际成本，不能称零成本。

### 时间预算须先解决

现有worker不知道deadline，模型 `urlopen(timeout=300)` 是socket等待约束，不等同于整次操作的严格墙钟上限；xvlog也没有本地超时。外层最终会终止worker，但新增可选步骤不能依赖“等到杀掉就算成功回退”。

实施前在实验配置冻结：最低复查剩余时间、模型子阶段上限、编译上限、清理/返回余量；数值先由本地假服务和限时EDA验证确定，不把R2平均8.55秒当作尾延迟保证。准入条件为 `remaining >= llm_cap + compile_cap + cleanup_reserve`。每个子阶段同时受到绝对请求截止点约束，编译结束前仍重新检查预算。无剩余预算就返回已有候选。

如果采用单独的模型请求子进程限制墙钟，只管理本轮创建的子进程，并与现有worker进程组监督兼容；必须测试父进程退出后无遗留本轮EDA子进程。**客户端断开并不证明共享模型停止计算**：故障试验要核对请求是否已完成/取消，不能只看到客户端退出就释放模型槽，更不能杀共享模型来实现取消。若不能安全证明取消，首版真实试验先不注入共享模型中的超时，只做假服务超时验证，并把现场这一项记为未验证。

### 候选采用规则

在开始可选复查前，以成功编译源码为 `accepted_source`，保存其SHA-256；整个可选阶段 `solution.v` 保持这些完整字节。新回复先放内存/独立临时文件，不能先覆盖正式返回文件。

新候选需要同时满足：非空、未因length结束、完整TopModule、不使用文件访问或include、不缺自带子模块、接口与原规格一致、独立xvlog成功。接口比较只支持可可靠解析的范围，不能“无法解析也算相同”。通过后同目录写临时文件并原子替换 `solution.v`；不满足、异常、超时则保留旧候选。回复与旧源码相同应记录unchanged，不算修复。

**编译成功、接口相同、或者选择器改为skip，都不证明功能更好。** 例如把 `>>>` 改成 `>>` 也会导致skip，却不满足算术右移。首版离线实验采用上述统一规则、之后独立判分和探针检查；线上不能读取这些判分来挑答案。若更改采用规则（例如新增最小差异白名单），必须另冻结版本，对C/D同时应用，不能见结果后择优。

## 4. 必须补的trace证据

复用现有 `trace()`，增加少量事件，不另建日志系统。现有`llm_start/llm`只有墙钟时间戳和token，缺乏可靠单调计时区间，不能把两条任意trace的跨度称为真实求解耗时。

| 事件 | 至少保存 |
|---|---|
| 实验元信息 | 实际runtime、selector、技能、复查模板hash；模式off/observe/C/D；调用和时间上限 |
| `review_select` | 当前candidate与prompt/interface合并文本hash、decision/reasons/findings、selector单调耗时、异常类型 |
| `review_budget` | 已用/剩余调用数、剩余请求时间、准入/跳过原因；在调用前记，不从完成后反推 |
| `review_llm_start/end` | request hash、模型与配置、独立call id、输入/输出token、缓存字段（若服务提供）、finish、单调起止/时长、错误/取消状态 |
| `review_validate` | 新源码hash、各静态门结果、xvlog返回码/时长、日志路径及hash、预算到期情况 |
| `review_commit` | accepted/rejected/unchanged、原/新/最终源码hash、拒绝原因；不以“selector不再报警”代替功能结论 |
| 请求末尾 | HTTP或CLI总墙钟、是否deadline、最终源码hash、实际模型调用数、返回源original/reviewed |

绝对路径、命令、进程归属可保存在实验侧证据；HTTP仍恰好返回既有四字段，不在产品接口添加实验字段。不得记录令牌或凭证，不向模型提供官方verdict、测试台、参考解、探针输入输出或题号专用答案。

## 5. 两种成本必须分开

定义O为原逻辑不复查，C为同一选择器触发的普通复查，D为同一选择器触发的符号清单复查。另设observe仅运行选择器、绝不调用模型，可测接入本身开销。

- **D−O**：部署这项机制的总额外成本，含selector、复查输入构造、额外模型调用、新候选检查与文件操作。整体均值还受真实触发比例、预算跳过比例影响。
- **D−C**：在已经愿意付出一次复查的条件下，清单文本相对于普通复查的增量。它不能代表部署开销。
- R2目标题实测D平均8.55秒、C平均7.73秒，约0.83秒是两种复查间差值。8.55秒也只是该题两次模型调用观测，不含新增编译或完整服务路径，不是下一轮性能承诺。
- R2b全156文本扫描约0.0152秒仅为本机热进程、已加载字符串的静态函数时间，不含启动、IO、模型和EDA。不能直接除156加到赛事预算后宣布成本可忽略。
- 汇总每请求HTTP总墙钟、实际额外调用、输入/输出token、各阶段时间、预算跳过/超时、均值/中位/max和原始逐样本表。小样本不报告有意义的p99保证；离线官方判分及探针耗时另列。

## 6. 最小验证顺序（均为下一项，未执行）

### A. 无模型、无云端：先证实接入不会丢答案

复用 `tests/test_official_contract.py` 的本地FakeModel与临时包方法，不改现有正式包；测试通过真实 `run_job/solve` 调用隔离runtime，而不只直接调用选择器。

1. off与原runtime对固定回复得到完全相同源码与模型调用数；observe只多trace，不改变候选；baseline路径逐字节保持。
2. 普通xvlog成功、声明补丁成功两个出口都检查实际已接受源码；skip/abstain/异常/预算不足均零额外调用。
3. 第一轮成功可触发一次；模型编译修复用尽预算后不能再调用；`RTL_REPAIRS=0`不能复查；C/D使用相同预算和验收规则。
4. 可选回复空白、length、非法JSON、缺module、错误接口、include/fileIO、缺子模块、xvlog失败、模型超时、xvlog超时：逐项验证返回原源码hash，临时新代码从未成为最终答案。
5. 已接收候选以后在复查等待/验证/写临时文件阶段中止worker：保留完整旧候选或完整新候选，不出现部分写入；只清理本轮子进程。
6. “把>>>改为>>导致选择器skip”的错误回复不能被记录为已证明修好；功能优劣留到独立探针，防止trace把规则消失写成成功。
7. 输入目录放隐藏文件canary，确认模型请求和选择器从不读到；HTTP仍保持四字段和deadline行为。

### B. 冻结归档候选：验证O/C/D路径与成本归属

这一步**另立计划，不增加本轮R3 12调用**。先冻结隔离实现hash、输入、调用顺序、模型配置、时间准入值、采用规则与判据；禁止把“候选注入入口”暴露到正式HTTP接口。

最小开发集合可用已验证的115原错误、115修正后候选，以及五个R2b归档守卫。固定从同一“编译已成功”检查点进入，逐份运行O/observe/C/D；C/D只在review且有预算时调用，所以正常旁路项应0调用且返回完全相同hash。115每臂至少两次，D0/C0/C1/D1顺序预登记，无补采样；这仍只是集成烟测，不能当作独立泛化。

所有结果完成后再离线运行固定官方判定及已验证题面探针。空答按L0，环境失败按官方口径另报并阻止完整比较；任何官方L3与探针失败的冲突阻止晋级。成功条件包含：原候选绝不因可选步骤的基础设施失败丢失；旁路不变；D目标题优于O/C；没有新增正式或探针回归；完整记录额外成本。通过只进入下一阶段，不发布。

### C. 小批HTTP端到端：不能只测检查点

检查点试验绕过了第一次生成，所以随后必须对预先固定的小集合运行真实HTTP O/C/D，从题面开始生成、记录编译修复与复查的预算竞争。非触发题应没有额外模型调用；真实生成结果不同必须如实记录，不能强塞旧候选制造稳定性。固定模型、技能、runtime底座与参数；C/D仅复查文本不同，不将官方baseline当作C。

这一阶段通过后，才决定全量、独立题面和重要候选五样本投入。全量若运行应同时报告官方baseline移动；旧1/156触发比例不是未知题集触发率。若只有唯一已知题获益，优先寻找独立同类错误与更低成本的确定性修复对照，不持续重复115扩大成功样本数。

## 7. 本文结论

接入点很小，真正必须先解决的是**两个成功出口的一致性、共享调用/时间预算、可选复查失败时保留已编译答案，以及功能采用风险的独立测量**。这些问题适合小范围直接代码修改和行为测试，尚不需要新框架。
