# 选择器隔离接入：本地机制验证完成，尚未实测功能收益

## 结论与版本

**隔离原型已实现，Windows本地22项集成测试及42项相关回归全部通过。** 这证明规定故障下的预算、旁路和原答案保留行为；不证明真实模型能修好更多题，不授予稳定版或正式部署状态。

- 原型：`package/agent/runtime.py`，SHA-256 `318672f841430a864cd99fae4de712942258d0dcda7a1ad6b0567c71610f52c8`。
- 底座：正式开发包的 `728499f4`，仍是未通过既有全量采纳门槛的开发正确性候选；不能与历史0.7667成绩拼接。
- 选择器：R2b的原字节 `a13fbdb8528a9e1a7309364aa6d145f959d8bcbf94bb383a635510cb7a81547b`。
- baseline、启动脚本、upstream与两份skill逐字节保持。正式包及云端部署均未修改。
- 本轮只用本机假HTTP模型与受控编译器；**真实模型调用0、真实Vivado调用0、云端访问0**。服务器及共享模型未被操作，其当前健康状态没有在本轮重新探测。

## 已实现的行为

普通编译成功与声明自动修复成功统一进入可选复查，使用当时实际接受的源码。默认 `RTL_REVIEW_MODE=off`；observe只记选择，不发起复查；control/checklist只在选择器review且预算充足时发起一次额外调用。C/D只差符号清单文本，采用门与配置相同。

复查共享原来的调用上限：`RTL_REPAIRS=1`最多两次预算尝试；首答编译成功可用第二次复查，模型编译修复已耗尽预算时不能再复查。默认时间准入为31秒（模型20、编译5、清理保留6），并接收外层请求绝对单调deadline；这些是原型配置，尚未依据云端成本优化。

新候选单独保存，通过完整性、禁止文件访问、保守接口比较、子模块与独立编译门后，同目录临时文件加原子替换。此前 `solution.v` 始终保留完整旧稿。候选相同记unchanged；异常、空答、截断、接口改变、编译失败或超时均回退原稿。

客户端和编译子进程继承worker监督范围，日志直接写文件，避免后代持有PIPE导致等待。trace包含实际版本、选择与预算、请求和源码哈希、usage/cache/finish、采用原因与调用尝试计数。后者不是精确服务收到数，测试另以假服务实际收到的POST交叉核对。

## 独立集成测试证据

最终 `local_receipts.json` 保存45个用例记录、75次假服务POST；它们不是竞赛样本或真实模型调用。26个有完整请求证据的可选调用，其服务实际收到的请求重新算hash均与trace一致。日志为 `local_test_log.txt`、`related_test_log.txt`；环境、版本与机器可读结论见 `validation_summary.json`。

## 测试自身的纠正

保留三轮先行receipt，不覆盖失败证据。首轮5个失败来自夹具：单行模块缺预期末尾换行、故障标记放在endmodule之后被官方抽取截去。第二轮剩一个失败是断言误读监督事件（实际tool=supervisor、event=deadline）。第三轮22项已通过，但审查发现比较C/D提示时修改了共享字典，污染了C请求receipt；改为副本比较并按每用例切分编译日志，最终完整重跑后26个请求hash独立核验通过。先行轮不能当作最终原始请求证据。

没有因这些夹具问题修改runtime机制，最终测试绑定上述同一原型SHA。相关42项为26选择器、11声明修复及5官方契约检查，不冒称重新执行了历史完整281项主套件。
