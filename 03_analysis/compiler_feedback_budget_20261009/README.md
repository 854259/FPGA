# 编译诊断预算：仅超长日志保留不同关键错误

历史模型生成105中，一份7002字符编译日志的前2048字符包含locale警告、重复位宽警告和首个信号的重复错误，另外两个出错信号没有进入修复请求。这不证明补全诊断后模型一定能作对。

runtime的唯一行为变化是编译诊断格式：原筛选结果不超过2048字符时逐字保留；超长时保留每个错误消息/文件的第一条原始日志，优先ERROR/FATAL，再保留放得下的警告。字符预算仍为2048，不保证任意数量或单条过长错误都能完整保留。原日志、候选RTL、首请求、模型参数、8192输出预算、最多2请求/1修复及原判定不改。

AMD一次通过8项纯控制，回放343份原编译日志，338份诊断原样、5份改变。真实worker使用保留回复及模拟编译完成两次请求接线检查：首请求精确相等，第二请求只有诊断变化；这不是新模型执行或原生编译。AST核对其余runtime主体不变。全部17成员私有档案已在AMD/E盘核验；来源及执行索引见PUBLIC_RESULT.json。

保留为draft，不合并/部署/采用。5份改变中有1份来自历史修复成功的输出，后续必须验证该保护样本，而非只测失败题。下一步在消化现有132–136结果后，依据实际适用范围做固定单因素模型对照；首稿来源、两次请求、实际编译、原等级与历史/配对/成本门须绑定。没有新增FIFO，不改任何既有冻结包。

pure_stage.py需要AMD既有私有105档案和执行包内原/新runtime、原baseline、SOURCE_MANIFEST.json。运行只在AMD；测试阻止真实网络/子进程，用既有有界执行器运行。公开不含题面、模型回复、RTL、TB或原生日志。
