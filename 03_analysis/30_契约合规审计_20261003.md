## 1. SIGTERM 契约合规（本轮新增）

**契约原文（L287）**：

> 由赛事方的测试脚本强制，到点发 SIGTERM。**收到后须在 10 秒内退出**，
> 否则 SIGKILL，该题按 L0 计。

### 测法与结果

| 场景 | 退出耗时 | 契约要求 | 结论 |
|---|---:|---|---|
| 启动后 0.5 秒中断（3 道题） | **0.10s** | ≤10s | ✅ |
| **EDA 工具运行中中断**（深处） | **0.10s** | ≤10s | ✅ |

两种场景都以 0.10 秒退出，**远低于 10 秒上限**。

### 机制

`runtime.py` 在 `SIGTERM`/`SIGINT` 上注册 `cancelled()`：
先 `stop_tree(proc)`（对 worker 进程组发 `SIGKILL`），再 `SystemExit(128+signum)`。
`Popen` 用了 `start_new_session=True`，所以 `killpg` 能一次带走整棵子树。

### 产出行为

被打断时 `solution.v` 为 **0 字节**、`trace.jsonl` 已写入。
契约要求"退出码 0 = 产出了文件"，被打断属于异常路径，**不产出解答是正确行为**。

## 2. 附带发现：僵尸进程会累积（量级无害，不改）

### 现象

深处中断后，`ps` 里留下 `[xvlog] <defunct>`：

```
2254494  1  Z  [xvlog] <defunct>
2254586  1  Z  [xvlog] <defunct>
```

**成因**：worker 被 `SIGKILL` 后，它的 EDA 孙进程（`xvlog` 等）成为孤儿、被重新挂到 PID 1；
它们退出后**没有人回收**。

### 为什么不回收

```
PID 1 = jupyter-lab
```

**PID 1 是 `jupyter-lab`，不是 init，不承担回收孤儿的职责** → 僵尸一直留在进程表里。

现状：**机器上已有 92 个僵尸**（来自 `sshd`/`bash`/`tar` 等，不只我们）。

### 量级评估

```
容器 pids.max   = 618610
1560 样本 x 2   = 3120 个僵尸（且仅在样本被 SIGTERM 打断时产生）
占比            = 0.5%
```

**结论：不构成风险，不改。** 记录在案，以便日后若换成 PID 上限很小的环境时能立刻想起来。

**注意**：只在 **SIGTERM 打断**时产生。正常完成的样本，worker 正常退出、
父进程 `proc.wait()` 回收，**不留僵尸**。
