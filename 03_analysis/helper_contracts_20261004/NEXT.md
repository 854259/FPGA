# 下一步：正确稿保护与完整流程收益

本轮原始8a7抽取器已经得到一个不同任务的域内格式修复。保持这些输入／源码／结果冻结，不改32位或移位器来回填胜出，不重抽。quota达到97%前收尾暂停，独立工作区和双锁继续。

1. 先冻结正确稿挑战。至少覆盖单顶层、顶层前后的helper、注释中假TopModule、失活generate分支里的helper、重复顶层／不支持结构。关注A已通过而B发生变化的控制；本轮3个自然A均失败不能验证此风险。人工挑战是边界控制，不称新自然泛化。
2. 源码已有一个风险：8a7可以从完整回复重选TopModule，未要求其正文与baseline选出的程序完全相同。先实测注释／围栏中的模块选择是否会改变A已正确的程序。若确有回归，保护原顶层字节或弃权，不按题名补丁。编译成功不能证明功能相同。
3. 只在抽取改变时研究候选自身、不带TB的xvlog／xelab及真实警告检查。32位自然样例表明越界可以是警告而非非零返回码。普通候选错误／相关警告可回退原抽取；工具启动、超时、许可或基础设施错误必须停轮，不当成源码失败。固定输入、源SHA、进程归属、负控和预算；不给所有题增加展开成本。
4. 16位新源码由两个完全相同、纯组合的8位加法器接成。可研究“8位组件全域穷举＋严格原源码连接结构核对＋加法分解”的专用证书，以覆盖完整两态16位函数；必须验证实际helper原字节、全部输出、无额外代码／参数／时序作用，并拒绝任何结构差异。它不是泛用SV形式证明、四态或综合后等价，未实施前不得声称完整域已证明。
5. 保护门槛通过后才冻结完整流程同预算配对：原抽取及原缺模块复查路径，与候选抽取／守卫路径，用相同初始回复。实际对比最终数学正确性、A正确稿回归、模型调用与整条耗时；最终还需真实agent生成技能作为共同producer，不能只用official-baseline系统消息的初稿推导agent效果。

所有阶段只写自己的研究目录，先查额度和实时共享任务。对方持锁时做本地准备；只有双锁准入成功才运行EDA或推理。没有完整流程和独立正确稿证据前，不接入正式runtime、改历史分数或替换共享模型／实例。
