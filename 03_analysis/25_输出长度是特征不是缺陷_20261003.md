# 输出长度是特征不是缺陷：上限与"输出预算"规则都不该动

- 日期：2026-10-03
- 执行：原会话 Agent（工程负责人）
- 性质：**基于已有全量数据的分析**（零模型槽）
- 结论：**两个方向同时关闭**——压低 `RTL_MAX_TOKENS` 净亏；假设 H（输出预算规则）预期净亏，不跑

---

## 1. 起因：一次疑似"卡住"

全量配对跑到 139/312 时速率从 2.1/分 掉到 0.3/分。排查后**不是故障**：
模型正在生成 **4367 token 且仍在继续**（29.5 tok/s）。

但这暴露了一个此前没量化过的东西——**输出长度的分布**。

## 2. 分布：极少数调用吃掉大部分输出

| | 冻结版（156 题，168 次调用） |
|---|---|
| 中位输出 | **140 token** |
| p75 / p90 | 469 / 1003 |
| 最大 | 8192 |
| **≥2000 token 的调用** | **5 次（3.0%）**，占总输出的 **35%** |
| `finish=length`（截断） | 1 次 |

**即：绝大多数生成很短（中位 140 token），少数几次极长。**

## 3. 关键问题：超长生成最后成功了吗

**成功了，而且比例更高。**

| 最大输出区间 | 题数 | L3 | L3 占比 |
|---|---:|---:|---:|
| 0–200 | 94 | 75 | 80% |
| 200–500 | 28 | 21 | 75% |
| 500–1000 | 17 | 7 | 41% |
| 1000–2000 | 12 | 4 | 33% |
| **2000+** | **5** | **4** | **80%** |

逐题：

| 题 | 最大输出 | 等级 |
|---|---:|---|
| `Prob147_circuit10` | 8192（截断） | **L0** |
| `Prob145_circuit8` | 7475 | **L3** |
| `Prob070_ece241_2013_q2` | 6138 | **L3** |
| `Prob140_fsm_hdlc` | 3833 | **L3** |
| `Prob030_popcount255` | 2603 | **L3** |

**超长输出不是"话多"，是模型在啃难题——而且多数啃下来了。**

## 4. 方向一：压低 `RTL_MAX_TOKENS` → 净亏

| 上限 | 影响题数 | **伤到 L3** | 省下（摊薄/题） |
|---:|---:|---:|---:|
| 1024 | 15 | **7** | 6.6 秒 |
| 2048 | 5 | **4** | 4.1 秒 |
| 3000 | 4 | **3** | 3.2 秒 |
| 4096 | 3 | **2** | 2.1 秒 |
| 8192（现状） | 0 | 0 | 0 |

**按 2048 算**：

```
收益（代价）: 实测时长 19.75 → 15.65 秒，比值 0.840 → 1.06（封顶 1.0）
              代价 8.40 → 10.00  =  +1.60
损失（4 道 L3）: 题集得分 -0.0256
              能力分 -0.77、增益分 -1.50  =  -2.27
净: -0.67
```

**结论：不动 `RTL_MAX_TOKENS`。**

## 5. 方向二：假设 H（输出预算规则）→ 预期净亏，不跑

假设 H 原本要补回规则 9 的"输出不含推导注释、确保在预算内写完 `endmodule`"，
理由是 `Prob147` 在两种技能下都是 L0、且无运行时机制处理。

**新的证据改变了判断：**

- `--reasoning off` 下模型**没有内部推理通道**——那些 `//` 注释**就是它的思考过程**
- 上面 4 道 L3 题（`Prob145`/`Prob070`/`Prob140`/`Prob030`）**正是靠长输出解出来的**
- 要求"不写推导注释"≈ 要求"不要思考" → **很可能打掉这 4 道**
- 而收益只有 `Prob147` 一道

**预期：4 × L3 换 1 × L3，净亏 3 道题（约 −1.7 分）。**

11 规则那轮的实测（技能文本变化造成 10 题量级扰动，净亏 6 题）**正好印证这个风险方向**。

**决定：不跑假设 H。** 变体与脚本保留在仓库里存档，但标注为"经分析预判为负，未执行"。

**这省下约 3.2 小时模型槽。**
