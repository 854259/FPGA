计入提前退出与同进程探索阶段，实际启动过6个Vivado会话、112次MCP工具调用、6次lint和2次普通综合；6个会话都已关闭，额外两次slot准入拒绝没有启动任何会话。另有先行直接命令8次lint和1次普通综合；不把重复控制当成额外题目或成绩。

## 已冻结的来源与输入

- 规则来源：[比赛官方仓库](https://gitee.com/Vickyiii/rtlagent2026)，核验 HEAD `afd135e7ba5f6ec4c6d77e7c927c894327537801`。最终评测使用 Vivado 2026.1，器件 `xczu3eg-sbva484-1-e`；开发工具允许使用，最终智能体仍须在断网容器和规定本地模型资源下自主执行。
- 技能与例子来源：[AMD 官方 ROSS 仓库](https://github.com/Xilinx/ross-ai-assistant)，固定提交 `2cdc9eef1b6b5b17fa45f5e4d468e5483a1c92de`。`UPSTREAM.json` 记录38个原始文件的路径、字节数和SHA256；原始快照保存在忽略目录 `upstream/`。官方故障源码的字节未改，只调整实验目标器件。官方 README 的预期11项使用不同器件，本轮不要求逐项计数等同。
- 用户下载的 Linux MCP Server 2026.9.1：23,998,648字节、ELF；MD5 `d62b050db4316889a051da4c38661bd3` 与[官方发布页](https://www.amd.com/en/support/downloads/ross-agentic-ai.html)相同。SHA256、用户路径见 `BINARY.json`。二进制不提交 Git；AMD 技能仓库的 MIT 许可不代表二进制的再分发许可已审核。
- `RUN_SPEC.json` 在直接EDA之前冻结：两个配置、四份输入、8次lint及1次普通综合。`MCP_SPEC.json` 在真实会话之前冻结：同一比赛器件、三次lint和一次普通综合、零模型。
- 正控制：官方多故障例子及旧锁存器／未驱动／截断例子；负控制：完整赋值的组合逻辑。另保留模256语义守卫，告警不能成为擅自扩大题面接口的理由。

## 已完成的先行直接命令检查

8次lint都正常结束，却全部返回0项，包括两份故障正控制。默认 `.csv` 文件实际为1405字节空ASCII表；官方参数 `set_param synth.elaboration.rodinMoreOptions "rt::set_parameter linterCsvFile true"` 使其成为0字节无表头CSV，没有恢复故障检出。平均每次约12.01秒。这只证明命令与格式路径完成，诊断机制没有通过校准。

普通综合能报告真实未驱动与锁存器警告；官方例子也有重复case、复位优先级和未驱动信号等普通消息。普通综合消息与lint行分开保存，不填造lint结果、不把告警等同功能错误，也不把“零告警”写成正确。

`diagnostics.py` 绑定源码和日志SHA256、精确源文件与行号、重复消息位置，校验报告形状和计数，并要求两个正控制及正常负控制通过才授权解释零计数。10项研究测试通过，所有真实lint校准结果仍为false；原型不允许自动改代码。

## 真实 MCP 的运行方式

云端根目录 `/workspace/team/runs/fpga_owner/ross_mcp_20261004_v1`。先完成 `initialize` / `notifications/initialized` / `tools/list` 握手，读取实际工具schema，再启动一个本轮所属的无界面会话。使用官方二进制的 `--stdio` 原生进程模式、显式Vivado路径、单会话上限，关闭遥测、LSF和SSH工具；没有共享HTTP守护、文档KB或全局客户端配置。

`mcp_live_probe.py` 通过真实 `tools/call` 顺序调用 `vivado_start`、`vivado_execute`、`vivado_log_messages`、`vivado_status` 和只针对返回会话ID的 `vivado_stop`。v2同一会话的37次调用在44.86秒内完成，但连续创建／关闭工程仍出现 `Synth 8-9873` 模块覆盖告警，其跨例状态不能当成已验证隔离。v3改为每份固定输入启动新的Vivado进程，共四个先后会话，每次只保留一个；输入、目标与诊断门槛不变，v2原记录保留。实际Tcl命令直接由MCP执行，不用外部Tcl脚本冒称技能执行。测试版本、目标器件、固定故障和正常稿，收集原始日志与报告；这仍不是本地模型自主选工具的完整智能体测试，也不是未修改的官方技能全流程。

**本版本的状态目录限制：** `--state-dir` 管理端口／会话状态，但握手日志显示命令历史还写入 `/root/.vivado-ai/data`。没有修改HOME或全局配置；该历史写入作为实际副作用记录，原始日志不公开上传。不能宣称所有状态都仅在工作目录内。

每轮使用既有资源守卫，在共享slot与模型空闲确认后启动；守卫只清理核验过的本轮后代，核对模型身份、官方判定器、baseline和正式包前后哈希，并释放自己的slot。两次真实会话准入因另一任务占用被拒，没有启动Vivado；另一次实际启动后因研究脚本误用固定日志文件名提前退出。失败记录及v1源码完整保留；v2改为核验并使用工具返回的本轮日志路径，没有改变输入、诊断门槛或预算。

本轮守卫固定使用 `bde08582` 中的 `03_analysis/selective_runtime_integration_20261003/resource_guard.py`，SHA256 `59c4212cb77971406255690c0efab0593cb5c100b21cf9d22622a9917be5e66d`；与云端及本地原始证据逐字节一致。当前同名文件后续修订与本轮执行代码分开，不以新文件覆盖旧证据。

## 比赛中如何使用

1. 开发阶段用ROSS帮助梳理工具调用、生成候选、检查真实Vivado消息；记录出处、许可、工具日志、费用与失败边界。
2. 最终运行只输入官方允许的题面与候选。隐藏参考与官方TB不进入模型；自建TB必须来自题面，官方baseline保持原样。
3. 采用局部离线技能与工具链前，先验证可在规定基础镜像、Vivado 2026.1和断网条件下复现；KB要预先离线保存并审核来源。当前没有完成容器断网或MCP二进制许可审核。
4. 真实工具连接成功仅证明接入路径。要把诊断用于修复，必须另外做正确稿守卫、同预算修复对照、端到端成本和独立题集验证。当前lint未校准，自动lint修复保持关闭。
