# 更正：模型跑在 AMD GPU 上，不是 CPU

- 日期：2026-10-03
- 性质：**对我自己上一份记录（`21_代价项调优与带宽墙_20261003.md`）的更正**
- 影响：那份记录的**前提与解释都是错的**，但部分实测数据仍有效

---

## 1. 我错在哪

那份记录的开头写着：

> **没有 GPU**，模型跑在 CPU 上，而且只用 8 个线程。

**这是错的。**

### 错误是怎么产生的

我只检查了 NVIDIA 的设备与工具：

```bash
ls /dev/nvidia*        # 不存在
nvidia-smi             # 不存在
ls /usr/lib/.../libcuda.so*   # 不存在
```

查到这些"不存在"，就下了"没有 GPU"的结论。**我没有查 AMD 侧的任何东西。**

实际上：

```
/dev/kfd                      <- ROCm 内核驱动，存在
/dev/dri/card6, renderD133    <- DRM 渲染节点，存在
/usr/bin/rocm-smi             <- 存在
/opt/rocm-7.2.1               <- ROCm 7.2.1 已安装
```

### 更严重的是：证据就在我手上

`submission/manifest.json` 里写着：

```json
"serving": {
  "backend": "llama.cpp",
  "version": "0.5.0-dev c13fcbf (HIP, gfx1100)"
},
"model": { "measured_vram_gb": 18.98 }
```

**我在下结论前几分钟还打印过这个文件。** 它明确写着 HIP / gfx1100 / 18.98 GB 显存。

**这是我拿着否证却下了相反结论。** 不是信息不足，是没有去核对已有证据。

## 2. 事实是什么（已坐实）

```
rocm-smi           : Device 0, DID 0x744b, 26°C, PwrCap 241W, VRAM 39%
llama-server ldd   : libggml-hip.so.0, libhipblas.so.3, librocblas.so.5,
                     libamdhip64.so.7, libhsa-runtime64.so.1 ...
进程打开的设备      : 3 -> /dev/kfd    7 -> /dev/dri/renderD133
推理时 GPU 占用     : 100%
吞吐               : 900 tokens / 30.3 s = 29.65 tok/s
```

**模型通过 ROCm/HIP 跑在 AMD GPU 上，推理时 GPU 已打满。**

## 3. 哪些结论要撤、哪些还站得住

### ❌ 必须撤回

| 原结论 | 为什么错 |
|---|---|
| "没有 GPU，跑在 CPU 上" | 事实相反 |
| "`-t 8` 是配置浪费" | **GPU 推理下 CPU 线程本来就无关**，8 个线程是合理的 |
| "撞的是 CPU 内存带宽墙" | 前提就是错的 |
| "AVX-512 未启用可能影响性能" | GPU 在做矩阵乘，CPU 指令集无关 |

### ✅ 仍然站得住的实测数据

| 数据 | 说明 |
|---|---|
| 8/32/64/128 线程吞吐同为 29.3 tok/s | **实测有效**，但原因是 GPU 在算，不是 CPU 带宽 |
| 吞吐 ≈ 29.7 tok/s | 实测有效 |
| 构建只到 AVX2 | 事实有效，但与性能无关 |

### ⚠️ 需要重新判断的

**"代价项无法靠配置优化"这个结论**——它可能是对的，但**我给出的理由是错的**，所以不能靠那份推理支撑。

重新计算（这次是对的）：

- 19.1 GB 权重/token × 29.65 tok/s = **566 GB/s**
- 该卡显存带宽（gfx1100 48 GB 档）约 864 GB/s
- **达到约 65%**，GPU 占用 100%

**GPU 已打满，配置层面确实没有明显杠杆。** 但这需要 GPU 侧的实测才能确认（例如 `-b`/`-ub` 批大小、`GGML_CUDA_*` 环境变量、显存频率），**我没有做，所以不下结论**。

## 4. 对我自己流程的修正

**教训：判定硬件环境时，必须把两边的证据都查完，并且先读项目里已有的环境记录。**

具体新增两条纪律：

1. **下"没有 X 硬件"的结论前，必须同时查 NVIDIA 与 AMD（以及项目文档里已记录的环境）。**
2. **`manifest.json` / `MODEL.md` / 服务启动脚本里已经写明的环境事实，必须先读再判断。**

第二条尤其重要——**这次不是缺信息，是没有用已有的信息。**
