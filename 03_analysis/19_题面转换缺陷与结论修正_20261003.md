# 题面转换缺陷：模块名声明重复（我的 bug）

- 日期：2026-10-03
- 发现者：原会话 Agent
- 性质：**我写的 `build_rtllm_taskset.py` 的缺陷**，已修复
- 影响：**削弱了"增益不可迁移"这一结论**

---

## 1. 缺陷是什么

RTLLM 题面里本来有：

```
Module name:  
    multi_pipe_8bit
```

我的转换器要把它改成 `TopModule`。但**它收到的是参考文件里的模块名**（`verified_multi_pipe_8bit`），
而题面里写的是 `multi_pipe_8bit`——**正则匹配不上**。

于是走了兜底分支，在文首**又加了一行**：

```
Module name: TopModule        ← 我加的（第 1 行）
...
Module name:  
    multi_pipe_8bit           ← 原文的（第 7-8 行，没被替换）
```

**题面自相矛盾：先说要 TopModule，后面又说要 multi_pipe_8bit。**

### 为什么我当时的自测没发现

我本地验证时用的名字是**题面里的** `multi_pipe_8bit`，正则当然匹配成功。
**又一次在不是真实调用路径的地方验证。**

## 2. 影响的量化

| 组 | 题数 | agent 输出 `TopModule` | **未输出** |
|---|---:|---:|---:|
| 题面**重复**声明（23 题） | 23 | 21 | **2** |
| 题面只声明一次（21 题） | 21 | 21 | **0** |

出问题的正是 `multi_pipe_4bit` 与 `multi_pipe_8bit`——**两道都是 agent L0**。

对照组（21 题无重复）**零例**输出错误模块名 → 这个相关性不是巧合。

## 3. 对结论的影响

RTLLM 旧配对：agent **0.5182** / baseline **0.5591**，增益 **0.9268**。

修正这两道题的上限估计（若它们能达 L3）：

```
2 道 × 1.0 系数 = +2.0
题集得分 +2/44 = +0.0455
agent 0.5182 → 0.5637
增益 0.9268 → 1.008   ← 反超 baseline
```

**因此：「增益没能迁移到 RTLLM」这个结论，至少有一部分是题面缺陷造成的假象，不是模型或 skill 的真实表现。**

**必须修正的表述：**
- ❌ 不能说"增益在独立题集上塌了、说明过拟合"
- ✅ 应说"旧题集存在题面缺陷，其中 2 道题的失败可归因于缺陷；修正后的对照尚未重跑"

## 4. 修复

`bench/build_rtllm_taskset.py` 的 `load_prompt` 重写：

- **从题面自身解析被声明的模块名**，而不是用参考文件的模块名
- 只在题面确实没有声明时才在文首补一行
- 兜底条件改为"是否已声明 `TopModule`"，而不是"文本里是否出现过 TopModule 字样"

验证：重新生成 49 题 → **重复声明 0 处**（原 23 处），`multi_pipe_8bit` 题面现在只有一处
`Module name: TopModule`，端口表未受影响。
