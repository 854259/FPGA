### 3.1 为什么会这样（A 分析判断）

赛事把 40 分（最大单项）押在"相对**自己**裸跑基线的增益"上，而不是绝对通过率。

- iCoder 的**裸基线高得多**（0.7564 vs 0.6590，+0.097）：RTL 专精训练确实有效
- 但 agent 在它上面**加不动**（增益 1.015），所以 40 分的大项几乎归零
- Qwen 基线低、可提升空间大，增益 1.103，拿到 4.29 分

**基线越强，增益越难做。** 这不是 iCoder 的缺陷，是评分机制与模型选择的交互。

### 3.2 agent 的绝对水平两个模型接近——真正的瓶颈是 skill

| | agent | baseline | agent − baseline |
|---|---:|---:|---:|
| Qwen | 0.7269 | 0.6590 | +0.068 |
| iCoder | 0.7679 | 0.7564 | +0.012 |

Qwen 基线低于 iCoder 基线 0.097，但 agent 只低 0.041——**agent 把两个模型的差距压缩了一半以上**。也就是说流程在把模型差异"抹平"，产出水平趋同。

**这是本轮最重要的发现：瓶颈在 skill / agent 流程，不在模型。**

## 7. 结论与建议

### 7.1 模型选择

**不换 iCoder。** 保留 Qwen3.6-27B Q4_K_M 作为参赛基座。

iCoder 的价值在于它证明了"更强的裸模型不一定得更高分"，这为后续模型选择提供了判据：**选基座时要同时看裸基线高度和 agent 可提升空间，不能只看绝对能力。**

### 7.2 下一步优先级（按预期收益排序）

1. **修 skill**（最高优先级）—— 有模型无关的直接证据

   **两个模型上都回归的题（4 道）**，是 skill 稳定失效、与模型无关的最强证据：

   | 题目 | Qwen 基线→agent | iCoder 基线→agent |
   |---|---|---|
   | Prob094_gatesv | 1.00 → 0.20 | 1.00 → 0.20 |
   | Prob143_fsm_onehot | 1.00 → 0.20 | 1.00 → 0.20 |
   | Prob150_review2015_fsmonehot | 1.00 → 0.20 | 1.00 → 0.20 |
   | Prob154_fsm_ps2data | 1.00 → 0.20 | 0.20 → 0.00 |

   这 4 题**裸模型都能拿 L3**，加上 skill 后无一例外掉到 L1/L0。不是模型问题，是提示词把正确的解带偏了。
   其中 `Prob143` 与 `Prob150` 同为 onehot FSM，`Prob094` 与 `Prob154` 涉及状态/边沿语义——可作为首要排查对象。

   另有 **34 道题两个模型的 agent 都不达 L3**，是与模型无关的稳定失败池，可作为 skill 改进的第二目标。

   方法论：一次只改 skill，同配置重跑，与本次 Qwen 全量结果配对比较（Qwen agent 0.7269 / baseline 0.6590）。
2. **改善仿真正确性**，而非继续加固编译修复（编译失败只剩 9/22，仿真失败 42/39）
3. **代价项（10 分）尚未优化**：Qwen full156 3h49m，有压缩空间

### 7.3 不建议

- 不建议为了"能力分好看"而换更强基座——会牺牲 40 分的增益项
- 不建议同时改 skill 和模型——会失去归因能力
