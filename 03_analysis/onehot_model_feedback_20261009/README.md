# Prompt-derived one-hot feedback preparation

This is a separate unintegrated checker draft. The model must generate every submitted design. `graph_contract.py` is a parse-only projection of the previous complete-graph parser; the old `synthesize` function is omitted. The original parser body is unchanged after explicit CRLF normalization. The retained old156 intake admitted one prompt, so this direction has limited known coverage. No new156 scan is claimed.

`onehot_feedback.py` renders a testbench over both scalar input values and all zero/single/multiple-active state-bit combinations. The expected outputs follow the fully consumed prompt graph. It checks model RTL rather than emitting a design. A future qualified adapter may return up to eight measured mismatches with width-explicit binary inputs and the total mismatch count to the existing one-repair loop. Unknown prose or unsafe candidate constructs abstain.

The suite is an ordered finite simulation observation, not a proof of absence of history-dependent behavior or all scheduling effects. No testbench, contract table, reference design, task identifier lookup or official judge feedback is supplied to generation. Only actual measured counterexamples would enter a future repair. The draft does not change output tokens, request/repair limits, temperature, extraction or the official baseline.

AMD passed 14 new pure controls for expected values, compact TB rendering, runtime prompt/interface splitting, width/summary/count/order binding, X-valued observations, bounded counterexample count and malformed-log rejection. No old parser/native/worker suite was rerun. The largest-width rendering check verifies text size only; it does not establish native runtime or timeout suitability. `pure_stage.py` blocks subprocess and network operations in that control child.

The native `check` adapter is only statically prepared. It still needs independent positive and negative native controls, exact extracted model-DUT byte/feedback binding, fallback/worker integration and source-proof controls before any model comparison. Neither its native correctness nor a score improvement has been established. Do not deploy it or append it to existing frozen packets.

Existing132-136, their FIFO order, peer ownership and source hashes remain unchanged. There is no new evaluation ticket. Raw evidence stays in the private AMD root and E archive indexed by PUBLIC_RESULT.json. A Windows newline comparison failed before any AMD launch; its original transport was retained and the file-only comparison corrected, with graph/core source unchanged.
