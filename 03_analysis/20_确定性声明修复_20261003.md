# 确定性声明修复：零成本 +0.56 分

- 日期：2026-10-03
- 执行：原会话 Agent（工程负责人）
- 结论：**采纳**。`Prob058_alwaysblock2` 从 L0 升到 L3，**零模型调用**，代价约 1 秒编译。

---

## 1. 起因：一个我写错的记录

我在 `FREEZE_20261002.json` 里写过 agent 对 `VRFC 10-1280`（过程块赋值给非 reg）
有"确定性补丁，不花模型调用"。**本轮核实：当前 runtime 里没有这个补丁。**
`grep -n "1280|output reg|declaration|_patch"` 零命中。

所以那是一条**错误的记录**——补丁要么在旧 `agent.py` 里没被继承，要么从来没存在过。

## 2. 缺陷形态

VerilogEval 7 道 agent L0 里，2 道是这类声明问题：

```verilog
module TopModule (
    input clk,
    output out_always_comb,     // 端口是隐式 wire
    ...
);
    reg out_always_comb;        // 内部又声明 reg -> VRFC 10-9336 重复声明
    always_comb begin
        out_always_comb = a ^ b;   // -> VRFC 10-1280 赋值给非 reg
    end
```

正确的修法是**机械的**：端口改成 `output reg`，删掉内部重复声明。

另一道 `Prob134_2014_q3c` 表面同类，**实际不是**：它给**输入端口 `y`** 赋值，是语义错误，
文本变换修不了。**所以是 1 道题的机会，不是 2 道。**

## 3. 实现

`runtime.py` 新增 `repair_ansi_declarations(code, feedback)`：

- **只改编译器点名的信号**（从 `VRFC 10-1280` / `10-9336` 的报错里解析）
- 端口 `output [wire] x` → `output reg x`（已是 reg/logic 的不动）
- 删除函数体里重复的 `reg x;` 声明行
- **调用方重新编译验证**，通过才采用；不通过就走原来的模型修复路径
- 外层 `try/except` 包裹，任何异常等同于"没打补丁"

**关键安全性质：它永远不会让结果变差。** 补丁只在编译已失败时触发，且必须重新编译通过才被接受。

## 4. 端到端验证

**先把变换逻辑在真实解答上验证，再接进管道**，然后用官方判定器判：

```
轨迹事件:
  llm              round=0          <- 只有 1 次模型调用（与原来相同）
  lint             rc=1             <- 编译失败
  declaration_fix  rc=0             <- 确定性补丁触发

官方判定器: level=3   stages={compile:true, simulate:true, synth:true}   mismatches=0
总耗时: 7 秒
```

**对照**：旧 runtime 下这道题走模型修复，**花了 2 次模型调用仍以 L0 结束**。
新路径不仅修好了，**还更快**。

## 6. 测试

新增 `tests/test_declaration_repair.py`，6 个用例：

- `Prob058` 真实代码能被正确修复（端口改 reg、重复声明删除、其余逻辑与端口不动）
- 已经是 `reg` 的端口**不被改动**（返回 None）
- 无关错误**不产生补丁**
- 空反馈不产生补丁
- 缺 module 头不产生补丁
- 修复后函数体完整保留

**测试当场抓出两个 bug**：
1. 我用了 `head.end(2)` 但正则只有 1 个分组 → `IndexError`
2. `re.subn` **即使替换内容相同也会计数**，导致"已经是 reg"被误判为"有改动"

第二个 bug 尤其说明问题：**没有那条测试，这个补丁会对已经正确的设计反复做无意义重编译。**

全套测试 **82 个全过**。

## 7. 一次操作失误（已即时纠正）

而**那个路径不在 git 管理下**，所以还原静默失败，**候选 runtime 一度留在生效位置**。

脚本自身打印了 `还原后: 22e32251 (期望 82e3a72e)`，我据此立即从备份 `/tmp/runtime.ACTIVE.backup`
还原，并确认生效版回到 `82e3a72e006e35d6`、槽已释放、无残留进程。

**教训：还原必须验证哈希并显式断言，不能依赖一个可能不适用该路径的机制。**
