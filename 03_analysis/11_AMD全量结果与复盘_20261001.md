## 4. 核心发现

### 4.1 输出截断在本配置下已不是问题（推翻旧结论）

| | 本轮 AMD | 09-27 AutoDL |
|---|---:|---:|
| agent 调用数 | 167 | 213 |
| 因长度截断 | **3（1.8%）** | **79（37.1%）** |
| baseline 截断 | 2/156（1.3%） | 45 |
| 平均输出 tokens | 520 | — |
| 空响应 | 0/156 | — |

`agent.py`/`runtime.py` 均不传 `enable_thinking`，思考开关完全依赖服务端 `--reasoning off`。

**结论（A 分析判断）**：截断率从 37% 降到 1.8%，最可能的解释是关闭思考后生成长度大幅下降；vLLM 后端与 GGUF 量化差异是次要可能。**旧结论"输出截断是最大单一失分原因、下一步优先做动态 token 预算"只在使用未关闭思考的配置下成立**，本配置下应降级为低优先级。

**仍需注意**：3 次 agent 截断全部落在 `Prob070`、`Prob145`、`Prob147`，其中 `Prob070` 是回归题（baseline L1 → agent L0），即截断确实造成 1 题损失，但量级很小。

### 4.2 增益 100% 来自编译鲁棒性，逻辑正确性无改善

| 失败类别 | agent | baseline | 差 |
|---|---:|---:|---:|
| 编译失败（L0） | **9** | **22** | agent 少 13 |
| 仿真失败（L1） | **42** | **39** | agent **多 3** |
| 综合失败 | 0 | 0 | — |

把 L0 减少的 13 题拆开：**10 题升到 L3、3 题升到 L1**，同时有 10 题回归。净效应 L3 从 95 升到 105（+10）。

**结论（A 分析判断）**：agent 相对基线的全部增益来自"让代码能编译过"（编译自检 + 编译驱动声明修复）。在**功能正确性上 agent 反而略差**（42 vs 39 次仿真失败）。

这条对下一步优化方向是强指引：**继续加固编译修复的边际收益已经不大，真正的失分大头是仿真正确性**（42+39=81 次仿真失败 vs 9+22=31 次编译失败）。

### 4.3 跨平台对照：baseline 提升远大于 agent，增益比被压缩

| 模式 | 本轮 AMD | 09-27 AutoDL | 差值 |
|---|---:|---:|---:|
| agent set_score | 0.7269 | 0.6846 | **+0.0423** |
| agent L3 | 105 | 103 | +2 |
| agent L0 | 9 | 34 | −25 |
| baseline set_score | 0.6590 | 0.5167 | **+0.1423** |
| baseline L3 | 95 | 76 | **+19** |
| baseline L0 | 22 | 57 | **−35** |
| **增益比** | **1.103×** | **1.325×** | −0.222 |

**结论（A 分析判断）**：关闭思考后，**基线的改善幅度是 agent 的 3 倍以上**（+0.1423 vs +0.0423）。合理解释是：agent 本来就有编译修复机制，能从"输出被截断/编译不过"中恢复，而基线是单次生成、不重试、不修复，截断对它的伤害大得多。**当截断被消除后，agent 用来抵消截断的那部分优势随之消失，增益比自然下降。**

这意味着：**在思考关闭的配置下，"增益"这一项的竞争会更难做**，而"能力分"（绝对通过率）反而更容易提升。
