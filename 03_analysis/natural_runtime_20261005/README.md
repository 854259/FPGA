# 自然输入接入与调用监督工程包

本阶段补齐完整公开文件输入、HTTP返回确认、原生调用收据、异常计数与每次求解的外层监督。`TOOLS_SPEC.json`仅冻结工程源码；本目录没有真实执行所需的`RUN_SPEC.json`，不授权模型或EDA调用，不更换运行中比赛策略。

`runtime.solve_supervised`从公开输入检查前开始计时。固定300秒总预算分配为272秒工作、24秒清理、4秒封口；子入口`solve_child.py`先验证继承管道、实际父子进程、守卫、锁及冻结字节，再进入runtime。直接调用真实传输或独立启动子入口都会拒绝。单次最多2请求、8192 tokens、温度0、6条原生命令；不重抽、不因未确认或超时自动重试。

每个外部调用先持久化尝试，再分别记录进入调用边界、完整返回确认、收据完整度与异常。计数不把超时当作零调用。子进程被终止后，父入口按同一编号盘点正式日志和`.pending`残留：保留SHA、字节及解析错误，残留撤销该编号的确认。恢复失败也保存错误收据，并停止整阶段；不删除残留或重发请求。

监督仅清理该次启动、并验证PID/starttime/进程组/session的自有进程。Linux使用PID描述符，覆盖分离session的孙进程，不对整个进程组发信号，不管理共享模型或服务器。结束HTTP客户端不能证明服务器已取消模型任务，资源释放仍必须等待外层守卫确认空闲与清理。

同整任务首次父准入检查资源记录的新鲜度，绑定root/spec/resource/实际stage/锁；之后仍逐次核验模型完整身份、实际锁、936任务/35官方保护清单、源码、依赖及资格档案，只复用已验证的初始时间门槛。有效完整全156审计、原harness准入投影、真实OS/include隔离证据、适用时的14项原生控制均不可用假文档代替。

工程检查入口：`python -B run_checks.py`。Linux可加`--linux-owned-controls`执行仅属于测试的Python管道/监督与挂起父子进程清理。HTTP连接为内存模拟对象，原生编译器回调为模拟对象；临时测试守卫和资格文档不授予真实执行。具体方法数、跳过项、源码SHA和自有进程控制见`ENGINEERING_CHECKS.json`及`LINUX_CHECKS.json`，完整日志保留在忽略的`raw_evidence`。

仍待验证：生产守卫的完整接线、实际300秒超时、真实HTTP/EDA与系统隔离、正式原判定器、独立模型质量、五样本及目标单卡32GB/断网。旧ANSI快速返回和原C/P语义未完整迁移；272秒工作窗口是新的接入因素，不能继承先前P收益。原edge harness即使漏检复位，研究TB通过也不能恢复其原判定资格。有限解析支持不等于全302求解能力。

`ADMISSION_REVIEW.json`是修补前只读审查的历史记录，不是当前源码的执行许可或测量证据。下一步先完成FIFO61/62/63原始终态审计，再根据实际资格与漏检排除准备一个固定的新因素实验，未经完整门槛不启用真实接入。
