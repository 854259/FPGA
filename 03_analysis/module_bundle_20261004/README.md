## 问题与冻结条件

历史加法器有 `full_adder` 缺失的展开失败，但历史完整回复不在证据里，不能把旧失败直接归因于抽取。新实验先保存完整回复，同一回复分别经过 A：原样官方 baseline 抽取，B：保守完整模块抽取，然后运行相同已校准的穷举数学契约。

`RUN_SPEC.json` 在云端EDA与模型调用前冻结，25项执行源码／输入SHA和3项只读依赖SHA逐项验证。公开题面仅统一上一阶段发现的加法器顶层名字；请求使用原 baseline 系统消息、temperature=0、top_p=1、8192输出上限、120秒HTTP超时，4题各2次、8请求、0补抽。8回复全部保存后才判定16个配对候选；参考、测试台、成绩与诊断不进入模型请求。原 baseline 的单模块系统消息也是本轮限制，未改变其行为。

B只收集回复中已有的完整模块。先遮蔽注释／字符串，再识别唯一TopModule及名字不重复、可从顶层访问的辅助模块。重复顶层、残缺结构、递归、未连接模块、宏及不支持语法返回原抽取；单TopModule保持原字节。它是保守文本识别器，并非完整SystemVerilog解析器或正确性证明。不会生成缺失辅助模块、改功能语句或按判定选抽取。
