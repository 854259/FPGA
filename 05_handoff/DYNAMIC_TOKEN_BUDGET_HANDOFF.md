## 首选设计：反馈驱动的预算控制器 + RTL 输出 skill

预算由确定性程序计算；skill 规定代码输出要求。先不用强化学习、额外模型做难度预测或复杂多模型路由。

第一步分开“思考额度”与“总输出额度”，第二步才加入截断后的动态扩容。vLLM 0.28.0 文档提供 `thinking_token_budget`，支持时到达思考上限会切换到最终输出；必须先验证本模型、聊天模板、qwen3 parser 组合是否实际生效，不仅检查请求返回 200。

参考：https://docs.vllm.ai/en/v0.28.0/features/reasoning_outputs/#thinking-budget-control

只隐藏 reasoning 返回字段不等于减少思考 token；不把思考文本当成最终 Verilog。为诊断优先记录 token/长度/耗时统计，无需公开完整推理文本。

### 决策规则

| 观察结果 | 下一步 |
|---|---|
| 完整源码且候选编译通过 | 返回；不能据此自称 L3，L3 由外部评测 |
| length 且最终代码为空 | 核查 reasoning/content 分离及预算是否生效；后续请求优先限制思考并保留输出空间 |
| length 且已有不完整代码 | 有时间和上下文余量时适当增加总输出上限 |
| 完整代码但编译失败 | 传入具体诊断修复，不仅因编译错误就加额度 |
| 时间不足 | 不启动预计无法完成的请求；保留已有较好候选，按协议返回 |

完整性不能只看 endmodule 字符串；结合正确提取、模块与端口、源码结构及候选编译检查。保留完整候选时，避免后续不完整结果覆盖它；不能借用参考答案或外部测试台选择候选。

### 预算计算

每次请求的总输出额度取三者最小值：策略希望分配的额度、实际剩余上下文、剩余时间可支持的输出量。

- 上下文余量：16384 减去实际聊天模板 token 数，再减安全余量。必须考虑提示、前轮代码、诊断及模板特殊 token，不能用字符数估算或把输出直接设成 16384。
- 时间余量：整题 deadline 减已耗时，再扣请求准备/首 token 延迟、内部检查和响应返回的预留。外部参考仿真与综合不属于智能体内部解题时间，不直接混入公式。
- 吞吐估计：先用历史数据的保守统计，后续可用 EWMA 更新，仍留安全余量。非流式的 tokens/请求时长包含 prefill 等开销，只能视为有效吞吐估计。若记录流式首 token/结束时间，再分别估计。超时与排队不能当成正常解码速度。
- 硬性超时与进程回收仍是最终保护；预测不能保证不超时。
- 不在请求结束后“原地追加”额度。下一轮是新请求，计入现有一次修复预算；默认优先完整重生成，续写需另行验证拼接与正确性。

### 待实验参数，不是最优值

- 首轮总上限先维持 8192，只改变思考额度；候选思考预算 2048、4096。
- 确认代码截断后，下一轮尝试约 12000 总输出额度，仍由上下文和时间约束裁剪。
- 修复上限先保持 1 次，避免同时增加调用次数混淆结果。
- 当前 300 秒是开发试验预算，不是已公布的正式限时。可另开宽松预算实验；所有对照组使用相同外层预算，不混合统计。
- runtime 当前模型请求 timeout=300 固定；如实现动态预算，须向 worker 传递实际剩余时间，使用单调时钟，并相应调整请求/编译超时。仅改外层 deadline 不能同步改变内层超时。

### Skill 内容

最终响应直接给完整 Verilog；保留模块名、端口、方向、位宽；采用简洁可综合写法；按具体诊断修复，返回完整替换代码；检查声明和模块结构。不以自然语言“少思考”代替程序预算，不包含题号答案表或参考实现。

## 最小验证顺序

1. 能力探针：确认 thinking budget 被模型正确执行，输出提取正确，终止不会导致空内容或无效代码；先不改全局推理服务。
2. A 组保持现有配置；B 组总上限仍 8192，单独限制思考（2048/4096 分别记录）；C 组在选定 B 配置上加入截断后动态扩容。逐步比较，不一次改所有参数。
3. 约 10–15 题，包含 5 道退化题、其他失败类型和已通过控制题；按失败类别预先选题，不只挑可能改善的题。参考非 L3 的 4 题单独诊断，不计入优化有效性主判断。开发小集结论不能外推全量。
4. 每题重复若干独立运行，保持相同模型、数据、参数、修复次数；记录随机种子/确定性设置。temperature=0 重复可能相同，重复稳定不等于统计显著提升。
5. 比较完整代码比例、length 次数、L3、模型调用数、平均/较慢请求耗时、超时、原通过题退化数。不能只看 length 下降；完整但错误仍是失败。
6. 小集确认后，再新目录做 156 题及五样本验证。全部记录代码/skill/配置哈希，保留原始证据。
