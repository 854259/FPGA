## 已核对的组件

使用原安装器元数据选择 Linux Vivado、其必选依赖及 Zynq UltraScale+ MPSoCs 器件族；保留目标 xczu3eg-sbva484 所需文件。未按名称随意删除 Vitis：安装器要求的 HLS 依赖仍保留。

- 902 个 payload，与原厂元数据 MD5 全部匹配。
- payload：25,142,569,326 字节。
- 含安装器的文件树：26,368,561,948 字节，约 24.56 GiB。
- 组件元数据展开量：69,099,630,929 字节，约 64.36 GiB。这是容量预算，不是实际安装测量。
- 最小包：`Vivado-2026.1-Linux-ZynqMP-minimal.tar`，保留原 TAR 的权限及链接。其摘要见 `minimal-package-verification.json`。
- 原厂安装器内容未改写；精简离线组件组合是否被安装器完整接受仍需云端验证。

## 分阶段，避免重复占用

1. 新实例先检查 GPU 和 `/workspace` 实际可用字节。此时不下载模型、不复制 Python/ROCm 整套环境。
2. 本地通过 SSH 流式解包精简 TAR，服务器仅保存解包文件，不另存一份 TAR。上传脚本在上传前要求“精简 TAR 大小 + 69,099,630,929 + 8 GiB”可用空间；不足就停止，不开始传输。
3. 上传后的 `preflight_linux_space.py` 再核对 902 个组件 MD5，并要求至少 77,689,565,521 字节空闲。安装到 `/workspace/AMD`，配置见 `vivado-linux-minimal-config.txt`。临时目录也放在此工作区并监测剩余空间。
4. 运行原厂安装器后，检查版本、目标器件、许可证及一个小型仿真/综合任务。失败则保留日志，不把安装完成当成测试通过。
5. 只有安装验证成功且证据备份后，删除本次云端安装暂存目录，释放约 26.37 GB；本机原始包和精简包均保留。
6. 再下载实际使用的 Qwen3.6-27B Q4_K_M，约 19.1 GB，直接下载到最终位置。复用镜像已有 ROCm/Python，避免重复缓存、重复虚拟环境及多份模型。
7. 开始逐题测试；归档结果后再清理可重建的中间仿真/综合目录。保留候选 RTL、判定、关键日志和错误证据。模型下载前和每题启动前重新检查空间，至少保留 8 GiB；不足则停止并处理，不边测边撑满磁盘。

## 容量边界

| 阶段 | 预算，不含已有数据 |
|---|---:|
| 安装组件 + Vivado 展开文件 | 95.47 GB / 88.91 GiB |
| 上项 + 8 GiB 临时与余量 | 104.06 GB / 96.91 GiB |
| 清理安装组件后，Vivado + 模型 | 约 88.2 GB / 82.1 GiB |

因此，空的 **100 GiB** 工作区在元数据预算上有条件可行；**100 GB（十进制）** 不通过当前保守安装门槛。已有镜像文件、文件系统分配、安装临时量、额外依赖会影响实际可行性，不能提前保证装得下。若门槛不通过，需要额外临时挂载空间或更大磁盘；不能通过删除必要组件来假装解决。

## 双人共用要求（用户已确认）

- 新实例必须支持 SSH；给每位同学独立账号和各自 SSH 公钥，不共享平台密码或私钥。队友公钥仍待提供。
- Vivado、模型和公共题库各保存一份，由管理员安装维护、团队成员读取；每人使用独立输出目录。共享模型不等于重复下载或每人同时加载一份。
- 单卡 GPU 评测及大型综合任务串行排队，运行前确认无人占用。先由一个模型服务承载请求，公平排队，避免两人各起服务挤爆显存。
- 磁盘预算针对两个人的总占用。两人的结果均计入剩余空间门槛；不能为了腾空间删除另一人的文件。长任务结果定期备份到本机。
- 以上是待实施配置；目前没有运行中的新实例，也尚未创建队友账号。

## 上传入口

上传需实例提供 SSH 且本机已有可信连接记录；主机、端口由实际新实例提供，不沿用已销毁实例。

```text
python stream_upload_installer.py Vivado-2026.1-Linux-ZynqMP-minimal.tar --host 用户名@实际主机 --port 实际端口
```

脚本默认远端新建 `/workspace/vivado-offline-stage`；若目录已存在会停止，避免混入旧文件。上传不是自动安装。包内 `deployment` 提供配置、组件清单和 Linux 预检脚本。
