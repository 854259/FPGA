## 3. 新发现：必须先处理的三个问题

### 3.1 相同答案被判成不同等级

`Prob005_notgate` 的新旧 agent 答案逐字节相同：

```text

新 run: full156_runtime728_20261003    L2，系数 0.7
两次：mismatches=0，samples=239，tool_error=null
```

代码只是 `assign out = ~in;`。新轮 trace 没有声明修复事件。这次退步不能归因于 runtime 把代码改坏；判定输入、综合环境、工具执行或文件处理仍有未解释的差异。**现在尚不能指定是哪一种根因。**

原始文件在各 run 的 `full/agent/Prob005_notgate/s0/solution.v` 和 `full/results/agent.Prob005_notgate.s0.json`。本次读取的新轮外层 judge log 为空，不能把“没看到错误日志”解释成“没有错误”。

处理：不改原始 verdict，不人为把 L2 改成 L3，不重生成 RTL。等当前实验释放资源后，用独立目录对这份留存答案和固定题目重新判定，保存底层综合 stdout/stderr、返回码、Tcl、器件、授权信息和原始 verdict。核实 reference/testbench/判定器哈希，不仅核实候选哈希。

如重复结果不稳定，先按预定范围复验相同答案却变级的所有样本，不能只重判不利的一边、更不能取最高分覆盖旧结果。给出“原始结果”和“诊断复验”两张表。没有根因证据时，本轮比较需注明有效性疑点，不得声称 runtime 已导致相应退步。

### 3.2 部署验收脚本仍可能误杀共享模型

本次读取 `/workspace/team/deploy_accept.sh`，以下代码与“只动自己启动的进程”的注释矛盾：

```sh
MPID=$(pgrep -f "llama-server -m" | head -1)
kill -9 "$MPID"
```

它记录了启动前模型 PID，但没有据此限制故障注入；agent 也按进程字符串取第一个 PID。前置只检查 `official_eval.py`，不能覆盖其他模型用户。它调用 `/workspace/team/serve_all.sh`，也尚未证明这是最终提交入口的同一版本。

恢复阶段部分判据只检查 HTTP 200，没有同时要求 `ready:true`；最后还停止守护进程，却把残留服务写成待命。这只能证明当时有进程，不能证明持续恢复能力。

**在修正并核实归属前，不执行这个脚本。** 具体要求见任务 C。

### 3.3 xelab 的经济性否定尚不成立

`03_analysis/37_xelab检查_有条件的否定_20261003.md` 的判断还存在四个问题：

1. 将“修到 L1”当作收益下界；实际可能完全修不好，也可能产生回归，正收益尚无保底。
2. 只计能力分变化，漏算了 agent 分数变化带来的增益分变化。
3. 把 H3 的 trace 已记录区间均值 19.80 秒用于另一版本的完整耗时估算；口径和版本都不够匹配。
4. 成本函数有分段和封顶，且额外修复只在触发题发生；一次修复约 20 秒若只触发 1/156，均摊不是每题多 20 秒。“B ≥ 20.96 时免费”也没有计入额外修复时间。

举例仅用于反驳旧算式：假设增益满分线取占位值 2.5、baseline 固定、一题 L0→L3，能力与增益合计增量约 **0.5558 分**，不是 0.1923 分。沿用旧文的假设 T=19.80→20.96、B=16.58，代价损失约 0.4634，未计修复耗时的净值反而约 +0.0924。**这些是假设演算，不是上线收益或官方预测。**

正确动作是撤下“除非 B≥20.6，否则无价值”的强结论，暂不全量接入；用固定小实验测出修复成功率、回归率、触发率和同口径耗时，再作判断。不要为了修正算术，反过来宣布 xelab 必然值得。

### 任务 D：耐久与五样本质量分开验收

**前置：** B/C 通过；冻结版本，独占模型槽，使用唯一输出目录。先核对 `http_endurance.py` 和 `five_sample_quality.py` 的云端哈希。

先跑接口耐久：异常输入、极短 deadline、大请求体、错令牌、不存在路径、并发三请求、恢复后正常解题。按契约逐个检查响应，不以任意一个 200 代表全部通过。每步检查恢复后的 ready 状态，并看子进程、临时目录、显存和磁盘随请求数的趋势。

再冻结一个分层 20 题子集：覆盖声明修复、多驱动诊断样例、功能错、稳定正确、组合/状态机/算术及长耗时题。写明抽样目的；定向压力子集不能当作全 156 题成绩的无偏估计。

**20 题 × 2 模式 × 5 样本 = 200 次请求。** 两侧同题同预算，采用事先固定的交错顺序或分块顺序，保存 nonce、参数、版本及全部答案。温度为零也不保证底层执行逐次完全相同；相同输出本身既不是成功，也不是失败。

质量统计只调用官方汇总：空答按 L0 留在分母；工具错误单列；pass@1 是等级系数均值，pass@5 是每题最大系数。pass@5 不能代替正式 pass@1。报告完整采样矩阵、计分题数、空答率、等级变化和端到端耗时均值/P50/P95/最大值；内部 trace 区间和 judge 耗时另列。

**停止条件：** 版本混用、数据缺格、脚本过期、服务不可恢复或工具错误未解释时，先修问题，不扩大到全量。允许候选答错，不能把任意 L0 都当评测工具失败。

**扩大条件：** 子集流程成立、资源预算明确后，最终冻结版再跑完整 156 × 2 × 5 = 1560 样本。不要在每个小修改后重复全量；已留存 verdict 只因汇总脚本改动时，优先离线重建摘要，不重做模型推理。

### 任务 F：只推进有信号的小范围提分实验（**经济性公式 ✅ 已修正**）

**先修正分析文档 37 的收益/成本公式，不改官方 score。** 全量 xelab 已证明稳定版只新增检出 Prob156，四道 H3 回归可作为诊断回归样例，不能计作稳定版四道潜在新增收益。

先用稳定版 Prob156 保存的失败候选，给定题面、候选及真实 xelab 诊断，执行固定预算修复。配一个预算相同、只要求重新检查的无诊断对照，以区分“诊断有效”和“多生成一次有效”。一次小实验只回答可行性，不据一个成功样本估计通用修复率。

修复前固定尝试数、接纳规则、耗时记录与停止条件；模型看不到官方参考、隐藏测试台或离线失配答案。官方判定仅用于离线评价，不能用其挑选正式运行时本来挑不到的最佳候选。

随后补正常守卫样例，测误触发和回归。证据支持后，才考虑更大的配对验证、选择性展开检查和最终上线。不要用宽泛文本替换任意删除驱动；“去掉报错”不等于行为正确。

经济性统一写成：

```text
Δ总分 = 30 × ΔA
       + [官方 gain_score(A_new, baseline) − gain_score(A_old, baseline)]
       + 10 × [min(B / T_new, 1) − min(B / T_old, 1)]
```

其中官方 B、增益满分线未知时只能报情景分析；实际实现调用官方增益函数并遵循上下限。T 使用同版本、同口径的请求总耗时；只在触发题发生的修复成本按实际频率累计。代码覆盖、修复成功、得分净增和成本可接受是不同层级的证据。

38 道 L1 按满系数 1 计算尚有 30.4 的系数缺口，6 道 L0 共 6，功能类占当前缺口约 83.5%。这只说明长期应关注功能，不保证这些题都可修。挑一个题面可定义、运行时可识别的子类，明确诊断和局部修复，再用未参与调整的题验证；不凭首失配时刻统一补零，不继续追加全局规则。

全量综合测量降为后续任务：先查清 Prob005 相同候选变级，再用已保存候选做无模型的定向覆盖检查。只有发现真实、可操作的综合诊断且代价可接受，才扩大 156 题测量或接入每次求解。
