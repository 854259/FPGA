另建一份本队没有用于调参的冻结验证集。来源可以是合规的新公开任务，或队友根据明确规格独立设计的题及变体；先从能严谨验证的一小批开始，不为了凑数量引入歧义。测试台需有正对照、预定错误实现的负对照和覆盖说明。冻结输入、评分与排除标准之后再看候选成绩。

限制对这份验证集的反复访问：只在候选通过开发验证或研究里程碑时使用。读过并据其调整的题就转为开发资料，不能继续宣称未参与调参。参数变体/同模板任务按来源和模板分组，避免一份模板同时冒充训练和独立验证。

修改评分摘要时优先重算留存 verdict；修改测试台时优先复判留存候选；只有生成条件确实变化时才需要新推理。预算集中于新增信息。

## 4. Codex 的执行与复核循环

每次接手先核对实际现场、最近记录与未提交改动，保留其他人的工作。使用已有状态文件记录当前任务、下一步与阻塞项，不另建复杂调度系统。

1. **选择一个问题。** 从队列中挑优先级最高且不被阻塞的任务；写明假设、唯一变量、运行时可用信息，以及“什么观察会否定它”。
2. **先做最便宜的验证。** 能从现存候选、日志或无模型回放回答的问题，先不生成新答案。判定异常先保留底层证据，不能重跑到满意为止。
3. **冻结小实验。** 写清目标题、正常守卫、对照、调用/耗时预算、停止条件、输出目录和采样顺序。探索可以灵活，但改变设计后要新开实验标识。
4. **执行并收尾。** 获取共享资源归属，记录每次生成和判定版本，检查实际产物和退出码。失败留下证据，按归属清理，确保锁与服务状态真实。
5. **分级处理结果。** 无效实验先修方法；有效但否定的实验归档并换方向；有信号的候选进入扩大验证，不立即替换稳定版。
6. **自主推进下一项。** 常规实现和预定实验无需问“要不要继续”。争议结论保留为候选，由 Codex 对原始证据独立复核，同时推进不依赖该结论的任务；只有用户才能决定的实质资源或范围变化才等待用户决定。

实验规模的建议梯度：无模型证据检查 → 数个故障样例及守卫 → 约 8–20 题的小实验 → 约 20–40 题的重复筛选 → 156 题配对 → 未用于调整的验证集 → 重要候选五样本及部署验收。数字是起点，可根据机制覆盖与成本调整，不机械填满所有层级。

不要因小样本胜出就宣称显著有效。原始均值、逐题差分、样本数和重复情况先报告；若用统计区间，按题聚合或按题重采样，不能把同题的五次样本都当独立题扩大证据。

同预算修复对照衡量“机制是否有效”，正式裸模型 baseline 衡量“比赛增益”，两者都需要，不能互相替代。实际总分调用官方函数，未知 B 和满分线只做明确标注的情景比较。

## 5. 候选晋级与自主决策

| 层级 | 允许声称 | 晋级依据 |
|---|---|---|
| 想法 | 有待检验的机制 | 运行时拿得到信号、实验可执行 |
| 原型 | 在指定样例上可工作 | 有对照、无信息泄漏、原始产物齐全 |
| 候选 | 在开发验证中值得扩大 | 重复观察、正常守卫、收益与成本同时记录 |
| 稳定版 | 在规定范围内经过验收 | 全量配对、适当重复与跨来源验证、契约与恢复检查、可回退 |
| 最终提交 | 冻结并可复现交付 | 最终包一致性、正式协议、可获得的目标环境验证、文档与演示一致 |

既有实验按已经写下的判据处理，不得事后改门槛。本计划用于安排后续实验，不把旧实验的单轮“分数不下降”自动升级成以后所有候选的充分发布条件。

以下情况停止对应重型实验：归属不清、版本混用、判定链不可信、输入泄漏、超出预设资源预算、反复出现同一基础设施故障。停止该项后选可独立推进的分析/数据任务；只有安全下一步都依赖用户信息时才等待。

首次小实验没有信号时分析失败机制；仅在有明确新证据或新机制时补一次修订实验。多次同机制有效否定后归档，不立即再跑全量。没有硬伤但证据不足的方向可留队列，标清重开条件。
